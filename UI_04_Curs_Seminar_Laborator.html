1. Concepte fundamentale privind arhitectura calculatoarelor

Un calculator este o combinație de componente hardware și software prin care se colectează date de la dispozitive de intrare, care sunt convertite în informații utile prin execuția unor instrucțiuni software; rezultatul este trimis către dispozitive de ieșire (monitoare, imprimante).

🏛 Arhitectural

Atributele care contează pentru programator: setul de operații, tipurile de date și numărul de biți, mecanismele de I/E, regiștrii, modurile de adresare a memoriei.

🔩 Structural

Unitățile operaționale și legăturile dintre ele: semnalele de control, tehnologia memoriilor, interfețele cu perifericele, circuitele combinaționale și secvențiale.

⚙️ Funcțional

Patru funcții de bază: procesarea, stocarea și deplasarea datelor, plus controlul acestor activități (prin Unitatea de Control).

🔄 Cele patru funcții de bază, animate

Alege o funcție.

Organizarea ierarhică: cele 6 niveluri (Tanenbaum)

În „Structured Computer Organization”, A. S. Tanenbaum descrie calculatorul pe 6 niveluri. Fiecare nivel este o mașină (fizică sau virtuală) cu propriul limbaj și se construiește pe nivelul inferior. Doar programele din limbajul nivelului 0 sunt executate direct de circuite; celelalte sunt interpretate sau traduse într-un limbaj de nivel inferior.

⬇ Traducerea unei instrucțiuni prin niveluri

Urmărește cum instrucțiunea C a = b + c; coboară de la nivelul 5 până la circuitele logice.

2. Componentele unui sistem de calcul

Hardware

Mecanismele fizice pentru datele de intrare și rezultate, procesare și controlul componentelor de I/E și de stocare.

Software

Programe de aplicație (specifice utilizatorului) și programe de sistem (sistem de operare, compilatoare, linkeditoare, asambloare).

Date

Numerice, alfanumerice, grafice etc., într-o formă pe care calculatorul o poate utiliza.

Comunicare

Hardware și software care transportă programe și date între sisteme interconectate.

Componenta hardware

Model de bază: UCP (procesarea datelor), memoria internă (memoria centrală, RAM – acces aleator, același timp pentru orice locație), memoria externă (stocare pe termen lung), dispozitive de I/E (interfața om–mașină sau proces–mașină). Apasă pe o componentă:

Fig. 1 – Componente hardware de bază ale unui sistem de calcul.

Unitatea centrală de prelucrare (UCP)

Preia instrucțiunile binare din memorie, le decodifică, generează semnalele de control și prelucrează datele prin operații aritmetice, logice și de comparare. Are trei componente:

ALU

Unitatea aritmetico-logică: operații logice (OR, AND, XOR) și aritmetice (adunare, scădere) pe secvențe binare.

Unitatea de Control

Monitorizează hardware-ul, controlează intrarea/ieșirea datelor și fluxul de date în UCP. Interpretează instrucțiunile (decodificatorul de instrucțiuni) și emite comenzi (generatorul de comenzi).

Memoria imediată

Regiștrii: celule de memorie pentru stocarea temporară a datelor prelucrate de ALU. Dimensiunea lor determină dimensiunea datelor cu care lucrează procesorul.

Caracteristicile microprocesorului

Frecvența de ceas: ceasul sistemului generează un flux de impulsuri; o perioadă de ceas este cel mai mic element de timp al procesorului (MHz, GHz). O instrucțiune necesită de regulă mai multe cicluri; procesoarele moderne execută mai multe instrucțiuni pe ciclu.

Viteza de lucru se măsoară în MIPS (milioane de instrucțiuni pe secundă):

tUCP = 1/f  ·  CPI = Σ(CPIi·Ii) / IC  ·  T = IC·CPI·tUCP  ·  MIPS = IC/(T·106) = f/(CPI·106)

🧮 Calculator CPI și MIPS

MIPS depinde de setul de instrucțiuni: comparația între procesoare cu seturi diferite de instrucțiuni nu este concludentă.

Legea lui Amdahl

O îmbunătățire într-o singură direcție nu implică o îmbunătățire corespunzătoare a performanței de ansamblu. Dacă o fracțiune F din timpul de execuție este accelerată de N ori:

speedup = timp vechi / timp nou = 1 / ((1 − F) + F/N)   →   când N → ∞: speedup → 1/(1 − F)

3. Caracteristicile sistemului de memorii; metode de acces

Amplasare: memoria internă (principală, cache, regiștri) și memoria externă (discuri, benzi), accesată prin controlere de I/E.

Metode de acces la date

Alege o înregistrare țintă și pornește animația: compară cât durează accesul în fiecare tip de memorie.

Acces secvențial

Înregistrările se parcurg liniar: pentru a n-a trebuie parcurse primele n−1. Timp variabil. Ex.: banda magnetică.

Acces direct

Blocurile au o adresă unică după locația fizică; mecanism de citire-scriere partajat; timp variabil. Ex.: hard-discul.

Acces aleator

Fiecare locație are un mecanism de adresare propriu; timp constant, independent de accesările anterioare. Ex.: memoria principală.

Acces asociativ

Adresare după conținut: datele se identifică după (o parte din) conținut. Ex.: memoriile cache.

Organizarea memoriei și capacitatea

Memoria este o matrice de celule, fiecare stochează un bit. Capacitatea se măsoară în octeți (bytes, 8 biți) – cea mai mică unitate reprezentabilă și adresabilă. Un cuvânt de memorie (locație) poate avea 8, 16, 32 sau 64 de biți.

📏 Convertor de unități (multipli de 210)

Performanța memoriei

  • Timpul de acces (latența) – pentru RAM: timpul dintre cererea de citire/scriere și momentul în care datele sunt disponibile (ns); pentru acces direct/secvențial: timpul de poziționare a mecanismului de citire-scriere.
  • Ciclul de memorie – timpul de acces plus timpul suplimentar până poate începe un nou acces (legat de magistrala sistemului).
  • Rata de transfer – pentru RAM: 1/ciclul de memorie; pentru celelalte: Tn = TA + n/R.

4. Ierarhia de memorii

Memoria accesată direct de UCP este memoria principală; dispozitivele de stocare de backup formează memoria auxiliară. În memoria principală se află doar programele și datele folosite curent. Proiectarea e un compromis: acces mai rapid ⇒ cost/bit mai mare; capacitate mai mare ⇒ cost/bit mai mic, dar acces mai lent.

Fig. 2 – Organizarea memoriei pe niveluri ierarhice

Treci cu mouse-ul peste un nivel.

Valorile tipice afișate (latență, capacitate) sunt orientative pentru sisteme actuale și nu fac parte din suportul de curs.

Principiul localității referințelor

Localitate temporală: o locație accesată o dată are o probabilitate crescută să fie accesată din nou în curând (bucle, funcții). Ierarhia păstrează datele recente aproape de procesor.
Localitate spațială: locațiile vecine celei accesate vor fi probabil accesate în curând. Ierarhia transferă blocuri contigue de date.

Dacă data cerută se găsește pe nivelul i: hit (succes). Altfel: miss (ratare) și data se aduce de pe nivelul i+1. Hit time = timpul de acces la acel nivel; miss time = timpul de aducere a blocului de pe nivelurile inferioare.

Nivelurile ierarhiei

Regiștrii – cel mai rapid, mai mic și mai scump tip de memorie (zeci până la sute de regiștri): memoria locală a procesorului.

Memoria principală – rapidă, cu capacitate relativ mare; fiecare locație are o adresă unică. Realizată din circuite integrate semiconductoare: RAM (citire și scriere) și ROM (doar citire).

🔋 De ce are nevoie DRAM de reîmprospătare

Condensatoarele se descarcă în timp; controlerul citește periodic datele și le rescrie. Oprește reîmprospătarea și urmărește ce se întâmplă cu biții 1.

ROM BIOS stochează programul inițial de pornire, care lansează sistemul de operare. Variante: PROM (scrisă o singură dată după fabricație), EPROM (poate fi ștearsă), EEPROM (ștearsă electric și reprogramată selectiv de sistem).

Memoria cache – între regiștri și memoria principală; conține copii ale zonelor de program și date active. Dacă cuvântul căutat este în cache, e furnizat imediat; altfel se aduce din memoria principală, împreună cu locațiile vecine. Azi cache-ul are mai multe niveluri.

Multiprogramarea permite UCP să proceseze concomitent mai multe programe: când un program așteaptă o operație de I/E, altul folosește UCP. Sistemul de management al memoriei supraveghează fluxul dintre memoria auxiliară și cea principală.

Memoria externă (auxiliară) – capacitate mare, acces mai lent: discuri și benzi magnetice, discuri optice. Timpul de acces = timp de căutare + timp de transfer; de aceea datele sunt organizate în înregistrări sau blocuri.

Hard-discul

Mai multe platane așezate concentric, acoperite cu material magnetizat pe ambele fețe, fiecare față cu propriul cap de citire-scriere; se rotesc împreună la 3600 / 4500 / 5200 / 5400 / 7200 rot/min. Informația se înregistrează pe piste (cercuri concentrice) împărțite în sectoare, separate de spații intersector. Sectorul este cea mai mică unitate transferabilă. Capul nu atinge suprafața discului.

💿 Hard-disc animat

Apasă pe un sector al discului (sau alege pista/sectorul): brațul face căutarea (seek), apoi se așteaptă ca sectorul să ajungă sub cap (latența de rotație), apoi are loc transferul.

întârzierea medie de rotație = 0.5 / (rotații pe secundă)  ·  timpul de transfer = dimensiune sector / rata de transfer
timpul mediu de acces = timpul mediu de poziționare + întârzierea medie + timpul de transfer + overhead-ul controlerului

Memoria flash

Tip de EEPROM; memorie semiconductoare nevolatilă – nu are nevoie de alimentare pentru a păstra datele.

Discurile optice

Scriere și citire cu laser. ROM, WORM (write-once read-many), WMRM (rescriptibile). Ex.: CD-ROM, CD-RW, DVD, DVD-R, DVD-RW, Blu-ray.

5. Adresarea memoriei

Managementul memoriei este o sarcină importantă a sistemului de operare. Obiective: alocarea eficientă (cât mai multe procese), protecția memoriei fiecărui proces, partajarea controlată a unor zone, performanța proceselor și a sistemului.

Împotriva fragmentării (zone libere prea mici), SO poate aloca mai multe zone neadiacente. Procesele pot rula chiar dacă nu sunt integral în memorie, iar memoria totală a programelor poate depăși memoria fizică: acesta este mecanismul memoriei virtuale.

Adresă virtuală – adresa folosită în program; mulțimea lor formează spațiul de adresare.
Adresă fizică – adresa folosită de procesor pentru memoria fizică; mulțimea lor formează spațiul de memorie.

Paginarea: memoria fizică se împarte în blocuri de dimensiune fixă (de obicei 4 KB) – cadre-pagină; spațiul virtual se împarte în pagini de aceeași dimensiune. (Alternativa cu blocuri de lungime variabilă se numește segmentare.) Doar paginile necesare imediat sunt aduse în memorie. MMU traduce automat adresele virtuale în adrese fizice, folosind tabelul de pagini al procesului și un cache special pentru intrările recente: TLB (Translation Look-aside Buffer).

🗺 Simulator: translatarea adreselor virtuale

Pagini de 4 KB ⇒ adresa virtuală (16 biți aici) = număr de pagină (4 biți de sus) + deplasament (12 biți de jos). Memoria fizică are 4 cadre; TLB are 2 intrări.

Rezumat

  • Un calculator combină hardware și software; organizarea internă se descrie pe 6 niveluri ierarhice.
  • Componente: hardware, software, date, comunicare. UCP = ALU + Unitatea de Control + regiștri.
  • Performanța procesorului: frecvența de ceas, CPI, MIPS; legea lui Amdahl limitează câștigul unei îmbunătățiri parțiale.
  • Metode de acces: secvențial, direct, aleator, asociativ.
  • Ierarhia de memorii (regiștri, cache, memorie principală, memorie auxiliară) se bazează pe principiul localității referințelor.
  • Memoria virtuală și paginarea: MMU translatează adresele virtuale în adrese fizice prin tabelul de pagini și TLB.

L2. Octeții unui întreg în memorie (little-endian)

#include <stdio.h>

int main(void) {
    unsigned int x;
    printf("x (hex) = "); scanf("%x", &x);
    unsigned char *p = (unsigned char *)&x;   /* vedem memoria octet cu octet */
    for (int k = 0; k < (int)sizeof x; k++)
        printf("adresa+%d: %02X\n", k, p[k]);
    printf(p[0] == (x & 0xFF) ? "little-endian\n" : "big-endian\n");
    return 0;
}

L3. Localitatea spațială: parcurgere pe linii vs. pe coloane

#include <stdio.h>
#include <time.h>
#define N 2048

static int a[N][N];

int main(void) {
    long long s = 0;
    clock_t t = clock();
    for (int i = 0; i < N; i++)            /* pe linii: adrese consecutive */
        for (int j = 0; j < N; j++) s += a[i][j];
    double t1 = (double)(clock() - t) / CLOCKS_PER_SEC;
    t = clock();
    for (int j = 0; j < N; j++)            /* pe coloane: salturi de N*4 octeti */
        for (int i = 0; i < N; i++) s += a[i][j];
    double t2 = (double)(clock() - t) / CLOCKS_PER_SEC;
    printf("pe linii: %.3f s, pe coloane: %.3f s (s=%lld)\n", t1, t2, s);
    return 0;
}

L4. Calculul timpului mediu de acces la disc

#include <stdio.h>

int main(void) {
    double sector_kb, rpm, seek_ms, rata_mb, overhead_ms;
    printf("sector(KB) rpm pozitionare(ms) rata(MB/s) overhead(ms): ");
    scanf("%lf %lf %lf %lf %lf", &sector_kb, &rpm, &seek_ms, &rata_mb, &overhead_ms);
    double rot_ms = 0.5 / (rpm / 60.0) * 1000.0;           /* jumatate de rotatie */
    double transfer_ms = sector_kb / (rata_mb * 1024.0) * 1000.0;
    double total = seek_ms + rot_ms + transfer_ms + overhead_ms;
    printf("intarziere de rotatie = %.2f ms\n", rot_ms);
    printf("timp de transfer      = %.4f ms\n", transfer_ms);
    printf("timp mediu de acces   = %.2f ms\n", total);
    return 0;
}

L5. Tabel cu legea lui Amdahl

#include <stdio.h>

double speedup(double F, double N) { return 1.0 / ((1.0 - F) + F / N); }

int main(void) {
    double F;
    printf("F = "); scanf("%lf", &F);
    int N[] = {1, 2, 4, 8, 16, 100, 1000};
    for (int k = 0; k < 7; k++)
        printf("N = %4d  speedup = %.3f\n", N[k], speedup(F, N[k]));
    printf("limita (N -> infinit) = %.3f\n", 1.0 / (1.0 - F));
    return 0;
}

L6. Descompunerea unei adrese virtuale (pagini de 4 KB)

#include <stdio.h>

int main(void) {
    unsigned int va;
    printf("adresa virtuala (hex) = "); scanf("%x", &va);
    unsigned int pagina = va >> 12;          /* 4 KB = 2^12 */
    unsigned int depl   = va & 0xFFF;        /* ultimii 12 biti */
    printf("pagina = %u (0x%X), deplasament = %u (0x%03X)\n", pagina, pagina, depl, depl);
    unsigned int cadru = 7;                  /* presupunem: pagina e in cadrul 7 */
    printf("adresa fizica = 0x%X\n", (cadru << 12) | depl);
    return 0;
}

1. Compresia datelor – generalități

Compresia datelor convertește un flux de date de intrare (mesajul generat de o sursă) într-un flux de ieșire de dimensiune mai mică, mai ușor de memorat sau de transmis. Fiind vorba de date binare, se urmărește reducerea numărului de simboluri binare necesare reprezentării.

Tipuri de date de intrare

  • text – ASCII (7 sau 8 biți) sau EBCDIC (8 biți, max. 256 caractere)
  • imagine – matrice de pixeli (bitmap) sau reprezentare vectorială (linii și curbe)
  • sunet – undă elastică, reprezentată printr-o funcție periodică
  • multimedia – combinație de text, imagine și sunet

Principiul comun: reducerea redundanței

  • redundanță alfabetică – unele litere apar foarte des
  • redundanță contextuală – grupuri de litere care apar împreună
  • redundanță spațială – pixeli adiacenți corelați

Secvențele frecvente primesc coduri scurte, cele rare primesc coduri lungi.

O procedură de compresie are două etape: un algoritm de compresie (generează o reprezentare cu mai puține simboluri binare) și un algoritm de decompresie (readuce mesajul la forma inițială).

Fără pierderi

Decompresia reface exact datele inițiale. Obligatorie pentru texte, date numerice, imagini medicale sau militare, cod sursă.

Cu pierderi

Se pierd detalii nesemnificative; grad de compresie mai mare. Potrivită pentru sunete și imagini, unde o pierdere minimă de rezoluție e insesizabilă.

Compresie simetrică

Același algoritm aplicat în sens opus; compresia și decompresia au aceeași complexitate.

Compresie asimetrică

Resurse diferite; de obicei compresia e mai solicitantă (ex. compresia video).

🖼 Demonstrație: compresie cu pierderi prin reducerea nivelurilor de gri

Imaginea are 256 de niveluri de gri (8 biți/pixel). Reduce numărul de biți per pixel și observă cum scade dimensiunea, dar și calitatea.

Măsuri de performanță

raport de compresie = dimensiunea datelor comprimate / dimensiunea datelor necomprimate   ·   factor de compresie = 1 / raport

Avantaje: reducerea spațiului de stocare, utilizarea eficientă a lățimii de bandă (rată de transfer mai mare), reducerea timpului de transfer.

2. Aspecte generale privind codificarea

O sursă discretă generează simboluri dintr-un alfabet S = {s1, …, sn}. Codarea reprezintă fiecare simbol printr-un cuvânt de cod (șir de biți), folosind cât mai puțini biți. Cu lungime fixă sunt necesari ⌈log2n⌉ biți: 4 simboluri → 2 biți, 16 simboluri → 4 biți.

Dacă simbolurile au probabilități diferite, e mai bună o codificare cu lungime variabilă. Lungimea medie (numărul mediu de biți pe simbol):

l̄ = Σk=1..n p(sk) · l(sk)    (1)

🧮 Calculator: lungime medie, entropie, inegalitatea Kraft

Editează probabilitățile (sau frecvențele) și cuvintele de cod. Exemplul din curs: s1 → 5/18, …, s5–s8 → 1/18.

Proprietăți ale codurilor

Nesingular – toate cuvintele de cod sunt distincte.
Unic decodabil – două șiruri distincte de simboluri nu produc același șir de biți.
Instantaneu decodabil – niciun cuvânt de cod nu este prefix al altui cuvânt (proprietatea de prefix).

🔎 De ce contează proprietatea de prefix: decodorul blocat

Cod: s1 → 1, s2 → 01, s3 → 010, s4 → 000. Se recepționează 1010000.

Entropia informațională (Shannon)

Informația asociată unui simbol: i(sk) = −log2 p(sk) = log2(1/p(sk)) biți: cu cât simbolul e mai probabil, cu atât poartă mai puțină informație. Informația medie a sursei este entropia:

H(S) = − Σ p(sk) · log2 p(sk) = Σ p(sk) · log2(1/p(sk))    (2)

📊 Entropia unei surse cu 2 simboluri

Mută cursorul: entropia e maximă (1 bit) când simbolurile sunt egal probabile și 0 când sursa e complet previzibilă.

Lungimea medie e mărginită de entropie: H(S) ≤ l̄ < H(S) + 1. Prima inegalitate rezultă din concavitatea funcției logaritmice (Σ pk f(xk) ≤ f(Σ pk xk)); a doua se obține alegând l(sk) = ⌈log2(1/p(sk))⌉.

Demonstrația inegalității H(S) ≤ l̄
H(S) − l̄ = Σ p(sk)[log2(1/p(sk)) − l(sk)] = Σ p(sk) log2(2−l(sk)/p(sk)) ≤ log2 Σ 2−l(sk) ≤ 0

Penultima inegalitate: proprietatea funcțiilor concave (Jensen). Ultima: inegalitatea Kraft (Σ 2−l ≤ 1).

3. Codificarea R-L-E (Run Length Encoding)

Unul dintre cei mai simpli algoritmi: secvențele repetitive („runs”) se înlocuiesc cu o singură apariție a simbolului și lungimea secvenței.

✍️ RLE pe text

în suport, primul grup apare ca (a,4), deși secvența începe cu 5 de „a”; corect este (a,5).

🖼 RLE pe o imagine binară

Matricea se transformă în vector prin concatenarea liniilor. Codul conține primul element, urmat de lungimile secvențelor. Desenează pe grilă (click / trage):

Exemplul din curs: 111100000011110000111111111001111 → 1 4 6 4 4 9 2 4 (primul element 1, apoi lungimile).

4. Codificarea Huffman

Fiecare simbol are o probabilitate determinată de frecvența sa. Se construiește un arbore binar de jos în sus:

  1. Lista simbolurilor se ordonează crescător după probabilitate; fiecare simbol este o frunză.
  2. Se iau primele două noduri (probabilitățile cele mai mici) și se leagă la un nod nou, cu probabilitatea egală cu suma lor.
  3. Cele două noduri se șterg din listă, iar nodul nou se inserează astfel încât lista să rămână ordonată.
  4. Se repetă până rămâne un singur nod: rădăcina. Ramura stângă primește 0, ramura dreaptă 1; codul se citește de la rădăcină la frunză.

🌳 Constructor animat de arbore Huffman

Când mai multe noduri au aceeași probabilitate, arborele nu este unic: poți obține coduri diferite de cele din curs (ex. ‘r’ → 10, ‘a’ → 11), dar lungimea medie rămâne aceeași (89/27 ≈ 3.29 biți/simbol pentru exemplul din curs), adică optimă.

Caracteristicile codării Huffman

  • Cele două simboluri cel mai puțin frecvente au cuvinte de cod de aceeași lungime, care diferă doar prin ultimul bit (ex. ‘t’ → 00000 și ‘u’ → 00001).
  • Simbolurile frecvente au coduri scurte, cele rare au coduri lungi (‘a’, ‘r’: 2 biți; ‘t’, ‘u’, ‘m’, ‘g’, ‘ ’, ‘p’: 5 biți).
  • Este un cod instantaneu decodabil: niciun cuvânt de cod nu este prefixul altuia.

▶ Decodificare: parcurgerea arborelui

Se pornește din rădăcină și se urmează ramurile după biți până la o frunză; se emite simbolul și se reia din rădăcină.

Teorema Kraft–McMillan

Un cod cu lungimile l(s1), …, l(sn) poate fi unic decodabil doar dacă:

Σk=1..n 2−l(sk) ≤ 1    (5)

Pentru exemplul din curs: 6·2−5 + 2·2−2 + 2−3 + 3·2−4 = 1. Calculatorul de mai sus verifică inegalitatea pentru orice cod.

5. Codarea aritmetică

Nu atribuie fiecărui simbol un cuvânt de cod, ci transformă întreaga secvență într-un număr din intervalul [0, 1), pe baza probabilităților cumulative.

  1. Se pornește cu intervalul curent [0, 1).
  2. Pentru simbolul curent, intervalul se împarte proporțional cu probabilitățile simbolurilor.
  3. Subintervalul simbolului curent devine noul interval.
  4. La final, orice număr din ultimul interval (de obicei mijlocul) reprezintă codul.

🔭 Zoom animat pe interval

Decodificarea

Decodorul caută intervalul care conține numărul, emite simbolul și repetă în acel interval. Pentru 0.75: [0.3, 0.8) → s2; [0.7, 0.8) → s3; [0.73, 0.78) → s2; [0.745, 0.770) → s2. Decodorul știe când să se oprească fie din lungimea înregistrării, fie dintr-un simbol de sfârșit de secvență.

6. Codarea Shannon-Fano

Simbolurile se sortează descrescător după probabilitate. Mulțimea se împarte în două submulțimi cu sume ale probabilităților cât mai apropiate; una primește bitul 1, cealaltă 0. Se continuă recursiv până rămâne câte un simbol în fiecare submulțime.

7. Codificarea informației multimedia

Informația multimedia are dimensiuni mari: necesită spațiu de stocare mare și o lățime de bandă mare. Codificarea ei are constrângeri de calitate, timp de execuție/complexitate și format (continuu sau discret).

Tipuri de redundanță

  • spațială – pixeli vecini cu culori apropiate
  • temporală – cadre video succesive asemănătoare
  • spectrală – corelație între planurile de culoare R, G, B
  • vizuală – limitele percepției umane

Reprezentarea imaginilor

Tonuri de gri: cu n biți/pixel → 2n tonuri (8 biți → 256). Color RGB: 8 biți pe canal → 28·28·28 ≈ 16.77 milioane de culori.

🎨 Mixer RGB pe 24 de biți

Tehnici de codare entropică (fără pierderi)

Nu țin cont de natura informației: datele sunt secvențe de biți a căror semnificație e ignorată.

  • RLE: pixelii x1…xn → perechi (ci, li) culoare–lungime. Ex.: 2222222222 111…1 333…3 111…1 → (2,10), (1,15), (3,20), (1,28).
  • Eliminarea repetiției („Repetition Suppression”): n apariții ale unui caracter → un caracter-semnal (flag) + numărul de apariții.
  • Înlocuirea modelelor („Pattern Substitution”): modelele des repetate se înlocuiesc cu coduri, cele mai frecvente cu coduri mai scurte.
  • Huffman: folosită în JPEG și MPEG-1…MPEG-4.

Tehnici de codare cu informații despre sursă (cu pierderi)

Țin cont de tipul semnalului (audio, video) și de proprietățile lui; gradul de compresie depinde de semantica datelor.

〰 Compresie cu transformate (transformata cosinus)

Semnalul trece din domeniul timp/spațiu în domeniul frecvențelor. Păstrând doar primii coeficienți (frecvențele joase), se obține o aproximare foarte bună cu mai puține date. Acesta este principiul JPEG (transformata cosinus + cuantizare + RLE + Huffman).

JPEG

Imagini în tonuri de gri sau color, cu multe tonuri. Rate de compresie alese de utilizator (≈ 1/10 – 1/20). Exemple: fax color, imagistică medicală, DTP, arte grafice.

MPEG

Compresie video: imagini digitale și sunet, plus sincronizarea lor. Există mai multe standarde MPEG.

📍 Cuantizare vectorială bidimensională

Vectorul de intrare x se înlocuiește cu cel mai apropiat vector cod yi din dicționarul Y (distanța euclidiană minimă). Planul e împărțit în zone Si, fiecare cu un singur cuvânt de cod. Click pentru a adăuga vectori de intrare; Shift+click pentru a adăuga un vector cod.

🔗 Codarea diferențială (predictivă)

Pixelii învecinați sunt corelați. Pixelul p se compară cu un pixel de referință deja codificat: prefixul = numărul de biți cei mai semnificativi identici, sufixul = biții rămași după primul bit diferit (acela e dedus de decodor).

Alegerea pixelului de referință: primul pixel rămâne necodat; pe prima linie – vecinul din stânga; primul pixel din celelalte linii – pixelul de deasupra; ceilalți – pixelul de deasupra sau cel din stânga.

Eșantionarea: se transmit doar anumite secvențe de pixeli care conțin suficientă informație. Același principiu apare la sunet: digitizarea presupune eșantionarea undei continue; eșantioanele adiacente sunt corelate.

Rezumat

  • Compresia transformă un flux de date într-unul mai mic, reducând numărul de simboluri binare.
  • Principiul comun: reducerea redundanței – coduri scurte pentru secvențe frecvente, coduri lungi pentru secvențe rare.
  • Un cod este nesingular (cuvinte distincte), unic decodabil, instantaneu decodabil (proprietatea de prefix).
  • Entropia H(S) măsoară informația medie a sursei și este limita inferioară a lungimii medii: H(S) ≤ l̄ < H(S)+1.
  • Tehnici fără pierderi: RLE, Huffman, codarea aritmetică, Shannon-Fano. Tehnici cu pierderi: transformate (JPEG, MPEG), cuantizare vectorială, codare diferențială, eșantionare.

Laborator: algoritmi de compresie în C

L1. Codificarea RLE

#include <stdio.h>
#include <string.h>

int main(void) {
    char s[256];
    printf("sir: "); scanf("%255s", s);
    int n = strlen(s), i = 0, perechi = 0;
    printf("RLE: ");
    while (i < n) {
        int j = i;
        while (j < n && s[j] == s[i]) j++;      /* lungimea secventei */
        printf("(%c,%d) ", s[i], j - i);
        perechi++;
        i = j;
    }
    printf("\n%d caractere -> %d perechi (%d octeti)\n", n, perechi, 2 * perechi);
    return 0;
}

L2. Frecvențe de apariție și entropia unui text

#include <stdio.h>
#include <string.h>
#include <math.h>

int main(void) {
    char s[512];
    int f[256] = {0};
    printf("text: "); fgets(s, sizeof s, stdin);
    s[strcspn(s, "\n")] = '\0';
    int n = strlen(s);
    for (int i = 0; i < n; i++) f[(unsigned char)s[i]]++;
    double H = 0;
    for (int c = 0; c < 256; c++)
        if (f[c]) {
            double p = (double)f[c] / n;
            printf("'%c': %2d/%d  p=%.4f  i=%.3f biti\n", c, f[c], n, p, -log2(p));
            H += -p * log2(p);
        }
    printf("Entropia H = %.4f biti/simbol\n", H);
    printf("Minim teoretic: %.1f biti (fata de %d biti in ASCII-8)\n", H * n, 8 * n);
    return 0;
}

L3. Codul Huffman (variantă simplă, cu vectori)

#include <stdio.h>
#include <string.h>
#define MAX 512

int fr[MAX], st[MAX], dr[MAX], par[MAX], viu[MAX];
char simb[MAX];

int main(void) {
    char s[256]; int f[256] = {0}, n = 0;
    printf("text: "); fgets(s, sizeof s, stdin); s[strcspn(s, "\n")] = 0;
    for (int i = 0; s[i]; i++) f[(unsigned char)s[i]]++;
    for (int c = 0; c < 256; c++)
        if (f[c]) { simb[n] = c; fr[n] = f[c]; viu[n] = 1; st[n] = dr[n] = -1; n++; }
    int total = n;
    for (int pas = 0; pas < n - 1; pas++) {     /* n-1 noduri interioare */
        int a = -1, b = -1;
        for (int i = 0; i < total; i++)          /* cele doua minime */
            if (viu[i]) {
                if (a < 0 || fr[i] < fr[a]) { b = a; a = i; }
                else if (b < 0 || fr[i] < fr[b]) b = i;
            }
        fr[total] = fr[a] + fr[b]; st[total] = a; dr[total] = b;
        viu[a] = viu[b] = 0; viu[total] = 1; par[a] = par[b] = total;
        total++;
    }
    int rad = total - 1, biti = 0;
    for (int i = 0; i < n; i++) {               /* codul: urcare spre radacina */
        char cod[64]; int k = 0, x = i;
        while (x != rad) { cod[k++] = (st[par[x]] == x) ? '0' : '1'; x = par[x]; }
        printf("'%c' (%d): ", simb[i], fr[i]);
        for (int j = k - 1; j >= 0; j--) putchar(cod[j]);
        putchar('\n'); biti += k * fr[i];
    }
    printf("Total: %d biti, medie %.3f biti/simbol\n", biti, (double)biti / strlen(s));
    return 0;
}

L4. Codarea aritmetică (calculul intervalului)

#include <stdio.h>

int main(void) {
    double p[] = {0.3, 0.5, 0.2};        /* p(s1), p(s2), p(s3) */
    double cum[4] = {0};
    for (int i = 0; i < 3; i++) cum[i + 1] = cum[i] + p[i];
    int sec[] = {1, 2, 1, 1};            /* s2 s3 s2 s2 (indici de la 0) */
    double lo = 0, hi = 1;
    for (int k = 0; k < 4; k++) {
        double w = hi - lo;
        hi = lo + w * cum[sec[k] + 1];
        lo = lo + w * cum[sec[k]];
        printf("dupa s%d: [%.4f, %.4f)\n", sec[k] + 1, lo, hi);
    }
    printf("cod = mijlocul intervalului = %.5f\n", (lo + hi) / 2);
    return 0;
}

L5. Prefixul și sufixul în codarea diferențială

#include <stdio.h>

int main(void) {
    unsigned p, r;
    printf("pixel si referinta (0..255): "); scanf("%u %u", &p, &r);
    int prefix = 0;
    for (int b = 7; b >= 0 && ((p >> b) & 1) == ((r >> b) & 1); b--)
        prefix++;                              /* biti identici de la MSB */
    printf("prefix = %d\n", prefix);
    printf("sufix  = ");
    for (int b = 6 - prefix; b >= 0; b--)      /* sarim bitul diferit */
        putchar((p >> b) & 1 ? '1' : '0');
    putchar('\n');
    return 0;
}

Partea I — Curs

1. Expresii, operanzi, operatori

O expresie este o construcție formată din unul sau mai mulți operanzi legați prin operatori. Prin evaluarea expresiei se obține o valoare. Operanzii pot fi constante (5, 3.14, 'a'), variabile (x), apeluri de funcții (sqrt(x)) sau alte expresii puse între paranteze.

Valoare, tip și efect secundar

Evaluarea unei expresii produce întotdeauna o valoare de un anumit tip. Unele expresii au, în plus, un efect secundar (side effect): modifică o variabilă, afișează ceva etc.

lvalue și rvalue

Un lvalue (left value) desemnează o zonă de memorie cu identitate — de exemplu o variabilă — și poate apărea în stânga unei atribuiri. Un rvalue este o valoare temporară (constanta 5, rezultatul lui a + b), căreia nu i se poate atribui nimic.

Expresii constante

O expresie constantă poate fi calculată de compilator, înainte de execuția programului: 3 * 60, sizeof(int) * 8. Ele sunt obligatorii în unele locuri (dimensiunea unui tablou static, etichetele case). 2. Prioritate, asociativitate și ordinea evaluării

Ca în matematică, unele operații „se fac înainte”: în 2 + 3 * 4 se înmulțește întâi, rezultatul fiind 14, nu 20. Regula după care compilatorul decide cum grupează operanzii se numește prioritate (precedență).

Când doi operatori vecini au aceeași prioritate, decide asociativitatea:

  • stânga → dreapta pentru majoritatea operatorilor binari: 20 - 5 - 3 înseamnă (20 - 5) - 3 = 12, iar 100 / 10 / 5 înseamnă (100 / 10) / 5 = 2;
  • dreapta → stânga pentru operatorii unari, operatorul condițional și atribuiri: a = b = c = 0 înseamnă a = (b = (c = 0)), iar !!x înseamnă !(!x).

Parantezele au întotdeauna câștig de cauză: se grupează mai întâi expresia din parantezele cele mai interioare.

Regula scurtă (de la prioritate mare la mică) unari (! ~ - + ++ -- (tip) sizeof) → multiplicativi (* / %) → aditivi (+ -) → deplasări (<< >>) → relaționali (< <= > >=) → egalitate (== !=) → pe biți (&, apoi ^, apoi |) → logici (&&, apoi ||) → condițional (?:) → atribuiri → virgulă.

Exemplu rezolvat

x = 10 + 5 * 4 / 2 - 3 (x de tip int). Cea mai mare prioritate o au * și /; fiind egale ca prioritate, se aplică de la stânga la dreapta. Urmează + și -, tot de la stânga la dreapta, iar la final atribuirea:

  1. 5 * 4 = 20 → 10 + 20 / 2 - 3
  2. 20 / 2 = 10 → 10 + 10 - 3
  3. 10 + 10 = 20 → 20 - 3
  4. 20 - 3 = 17 → x = 17

În C nu există ::, .*, ->*, <=>, new/delete, throw; tot în C, operatorul ?: are un nivel propriu, imediat deasupra atribuirilor. Pentru expresiile obișnuite, ordinea este aceeași în ambele limbaje.

Prioritatea în practică: afișarea cu cout

În C++, << folosit cu cout își păstrează prioritatea de operator de deplasare (nivelul 7). Expresiile care conțin operatori de prioritate mai mică — relaționali, pe biți, logici, ?:, atribuire — trebuie deci puse între paranteze:

Prioritatea nu este ordinea evaluării

Prioritatea și asociativitatea spun doar cum se grupează operanzii, nu în ce ordine se calculează aceștia. În f() + g() * h() gruparea este sigur f() + (g() * h()), dar standardul nu precizează dacă f() se apelează înainte sau după g() și h().

Ordinea de evaluare a operanzilor este garantată doar pentru câțiva operatori:

  • && și || — operandul stâng se evaluează complet înaintea celui drept (iar uneori dreptul nu se mai evaluează deloc, vezi §6);
  • operatorul virgulă — întâi stânga, apoi dreapta;
  • ?: — întâi condiția, apoi o singură ramură;
  • în C++17, în plus: << și >> (stânga înaintea dreptei), atribuirile (dreapta înaintea stângii), indexarea a[b].

Consecința practică: nu scrie expresii al căror rezultat depinde de ordinea în care se evaluează operanzii (vezi §10).

Împărțirea / depinde de tipul operanzilor

  • dacă ambii operanzi sunt întregi → împărțire întreagă: rezultatul este câtul, iar partea fracționară se pierde (trunchiere spre zero): 7 / 2 = 3, -7 / 2 = -3;
  • dacă cel puțin unul este real (float, double) → împărțire reală: 7.0 / 2 = 3.5, 7 / 2.0 = 3.5.

Capcană: 1 / 4 este 0, nu 0.25! Variante corecte: 1.0 / 4, 1. / 4, 1 / 4.0, (double)1 / 4. Atenție însă: (double)(1 / 4) este 0.0 — conversia vine după ce împărțirea întreagă s-a făcut deja.

Restul împărțirii întregi %

  • se aplică numai operanzilor întregi: 7.5 % 2 este eroare de compilare (pentru numere reale există funcția fmod din <cmath>);
  • 7 % 3 = 1, -7 % 3 = -1, 7 % -3 = 1 — restul are semnul deîmpărțitului;
  • pentru orice b ≠ 0 are loc identitatea (a / b) * b + a % b == a; de exemplu −7 = (−2)·3 + (−1).

Împărțirea la zero și depășirea

  • Întregi: a / 0 și a % 0 au comportament nedefinit; în practică programul se oprește brusc (pe Linux: „Floating point exception”).
  • Reali: conform standardului IEEE 754, 1.0 / 0 dă inf, -1.0 / 0 dă -inf, iar 0.0 / 0 dă nan („not a number”).
  • Depășire (overflow): tipul int (32 de biți) are domeniul [−2 147 483 648, 2 147 483 647] — constantele INT_MIN și INT_MAX din <climits>. Dacă rezultatul exact iese din domeniu, pentru tipurile cu semn comportamentul este nedefinit; pentru tipurile unsigned rezultatul se calculează modulo 232 („se dă peste cap”).
De reținutTipul rezultatului unei operații se stabilește din tipurile operanzilor, nu din tipul variabilei în care se memorează rezultatul.

Paritatea numerelor negative

Deoarece restul are semnul deîmpărțitului, -3 % 2 este -1, nu 1. Testul n % 2 == 1 ratează deci numerele impare negative. Corect: n % 2 != 0 (sau n & 1).

Numerele reale sunt aproximări

float și double memorează valorile în baza 2, cu un număr finit de cifre: 0.1 nu se poate reprezenta exact, deci 0.1 + 0.2 este 0.30000000000000004. Consecințele pentru comparații sunt discutate în §5. În plus, INT_MIN / -1 depășește domeniul (rezultatul ar fi 2 147 483 648), deci este tot comportament nedefinit.

4. Conversii de tip în expresii

Un operator aritmetic binar lucrează cu doi operanzi de același tip. Dacă tipurile diferă, compilatorul convertește automat (conversie implicită) operandul de tip „mai mic” la tipul „mai mare”, apoi efectuează operația. Ierarhia, simplificat:

bool, char, short → int → long → long long → float → double → long double

Exemplu: int a = 5; char b = 6; float c = 9; — în a + b + c se calculează întâi a + b = 11 (int), apoi 11 + 9.0f = 20 (float).

Caracterele sunt numere mici

Un char memorează codul caracterului (codul ASCII). În calcule, caracterul participă cu codul lui:

ExpresieRezultatExplicație
0 + 'a'97codul lui 'a'
'a' + 198rezultatul este int

c - '0'7 pentru c = '7'valoarea cifrei-caracter

Coduri utile: ' ' = 32, '0'…'9' = 48…57, 'A'…'Z' = 65…90, 'a'…'z' = 97…122. Diferența dintre o literă mică și perechea ei mare este 32.

Regulile complete

  1. Promovarea întregilor. Operanzii de tip bool, char, signed char, unsigned char, short, unsigned short sunt convertiți la int înainte de orice calcul. Calculele nu se fac niciodată „în char”.
  2. Conversiile aritmetice uzuale. Dacă după promovare tipurile încă diferă:
    • dacă unul este long double, celălalt devine long double; altfel, dacă unul este double, celălalt devine double; altfel, dacă unul este float, celălalt devine float;
    • altfel ambii sunt întregi: cel de rang mai mic se convertește la cel de rang mai mare (int < long < long long); dacă unul este cu semn și celălalt fără semn, de regulă câștigă tipul fără semn (vezi capcana de mai jos).
  3. Conversiile se fac pe rând, la fiecare operator, nu pentru toată expresia deodată: în 1 / 2 + 1.0 împărțirea 1 / 2 se face în int (0) și abia apoi rezultatul se convertește la double: 0 + 1.0 = 1.0.

Conversii la atribuire

La atribuire, valoarea din dreapta se convertește la tipul variabilei din stânga — chiar dacă se pierde informație:

Conversia explicită (cast)

Se scrie (tip) expresie (stilul C) sau static_cast<tip>(expresie) (stilul C++, recomandat: este mai vizibil și verificat mai strict de compilator). Conversia explicită are prioritatea operatorilor unari, deci (double)s / n înseamnă ((double)s) / n.

Capcana signed / unsigned

Compilatorul avertizează (-Wsign-compare); tratează avertismentul ca pe o eroare. Capcana apare des cu v.size(), care are un tip fără semn: pentru un vector gol, v.size() - 1 este un număr uriaș.

Alte detalii

  • Conversia unui real care nu încape în tipul întreg destinație (de exemplu (int)1e10) are comportament nedefinit.
  • Dacă char simplu are sau nu semn depinde de platformă (cu semn pe x86, fără semn pe multe procesoare ARM). Pentru valori numerice mici, folosește explicit signed char / unsigned char.
  • Inițializarea cu acolade (C++11) interzice conversiile cu pierdere de informație: int x = 3.7; se compilează (x = 3), dar int x{3.7}; este eroare.

Comparațiile înlănțuite nu funcționează ca în matematică

În matematică 1 < x < 3 înseamnă „x este între 1 și 3”. În C/C++, 1 < x < 3 se grupează (1 < x) < 3: paranteza dă 0 sau 1, ambele mai mici decât 3, deci expresia este mereu adevărată. Forma corectă: 1 < x && x < 3. Din același motiv, 3 > 2 > 1 este fals: (3 > 2) este 1, iar 1 > 1 este fals.

Compararea numerelor reale

Pentru valori de ordine de mărime diferite se folosește o toleranță relativă: fabs(a - b) <= 1e-9 * fmax(fabs(a), fabs(b)). Valoarea specială nan nu este egală nici cu ea însăși: x != x este adevărat doar dacă x este nan.

C++20 a introdus și operatorul de comparație în trei sensuri a <=> b („nava spațială”), care spune dintr-o singură operație dacă a este mai mic, egal sau mai mare decât b; este folosit mai ales la definirea comparațiilor pentru tipurile proprii.

Evaluarea prin scurtcircuitare

Operanzii lui && și || se evaluează de la stânga la dreapta, iar evaluarea se oprește imediat ce rezultatul este cunoscut:

  • A && B: dacă A este fals, rezultatul este fals și B nu se mai evaluează;
  • A || B: dacă A este adevărat, rezultatul este adevărat și B nu se mai evaluează.

Regula se folosește intenționat pentru „gărzi”: condiția din stânga protejează operația periculoasă din dreapta.

Legile lui De Morgan

!(p && q) ≡ !p || !q   și   !(p || q) ≡ !p && !q. Exemplu: negația lui „x este în [a, b]” este !(x >= a && x <= b) ≡ x < a || x > b. Poți verifica orice astfel de echivalență cu verificatorul de echivalență din seminar.

Echivalențe și diferențe subtile

  • if (n) ≡ if (n != 0); if (!n) ≡ if (n == 0); if (n - 10) ≡ if (n != 10); !!x transformă orice valoare în 0 sau 1.
  • Logic sau pe biți? 1 && 2 este 1, dar 1 & 2 este 0 (01 ȘI 10 = 00). În plus, & și | nu fac scurtcircuitare și nu garantează ordinea operanzilor.
  • Tautologii și contradicții: (a > 0) || (a <= 0) este mereu adevărată; (a > 0) && (a <= 0) mereu falsă; x % 10 > 9 mereu falsă (restul la 10 este între -9 și 9).
  • Efecte secundare ascunse: în if (gasit || ++contor > 3), contor crește doar când gasit este fals — sursă frecventă de erori greu de găsit.

Capcane de prioritate

  • &, ^, | au prioritate mai mică decât ==: x & 1 == 0 înseamnă x & (1 == 0) = x & 0 = 0, pentru orice x! Corect: (x & 1) == 0.
  • Aditivii au prioritate mai mare decât deplasările: 1 << n - 1 înseamnă 1 << (n - 1), iar a + b >> 1 înseamnă (a + b) >> 1.

Comportament nedefinit și dependent de implementare

  • deplasarea cu un număr negativ de poziții sau cu cel puțin numărul de biți ai tipului (pentru int: ≥ 32) — nedefinit; 1 << 31 depășește domeniul lui int — folosește 1u << 31 sau 1LL << 40;
  • deplasarea la stânga a unui număr negativ — nedefinită în C și în C++ înainte de C++20;
  • deplasarea la dreapta a unui număr negativ — dependentă de implementare (de obicei se copiază bitul de semn): -7 >> 1 este -4, în timp ce -7 / 2 este -3.
RecomandarePentru manipularea biților folosește tipuri fără semn (unsigned): toate operațiile sunt complet definite.

Trucuri cunoscute

  • n > 0 && (n & (n - 1)) == 0 — n este putere a lui 2 (o putere a lui 2 are un singur bit 1); n & (n - 1) șterge bitul 1 cel mai din dreapta.
  • n & -n izolează bitul 1 cel mai din dreapta: pentru 40 (101000) dă 8 (1000).
  • x ^ x == 0 și x ^ 0 == x; de aici interschimbarea fără variabilă auxiliară a ^= b; b ^= a; a ^= b; — o curiozitate: nu este mai rapidă decât varianta clasică și eșuează dacă a și b sunt aceeași variabilă.

8. Operatori de atribuire

Atribuirea simplă v = expresie: se evaluează expresia din dreapta, valoarea se convertește la tipul lui v și se memorează în v. Operandul stâng trebuie să fie un lvalue (de regulă, o variabilă).

Atribuirea este ea însăși o expresie, a cărei valoare este valoarea atribuită. De aceea atribuirile se pot înlănțui; asociativitatea este dreapta → stânga:

v1 = v2 = … = vn = expresie  ⇔  vn = expresie; vn-1 = vn; … ; v1 = v2;

Atribuirea compusă

Operatorii += -= *= /= %= &= |= ^= <<= >>= scurtează scrierea: v op= e este echivalent cu v = v op (e).

Scriere scurtăEchivalentExemplu (a = 7)
a += 3a = a + 310
a *= 2a = a * 214
a %= 4a = a % 43
a /= 10a = a / 10 (elimină ultima cifră)0
a <<= 1a = a << 1 (dublare)14
Atenție la parantezele implicitea *= b + 1 înseamnă a = a * (b + 1), nu a = a * b + 1. Pentru a = 5, b = 2 rezultatul este 15, nu 11.

Conversii ascunse în atribuirea compusă

Operația se face în tipul comun, iar rezultatul se convertește înapoi la tipul variabilei: pentru int x = 5; x *= 1.5; se calculează 7.5, iar x devine 7. Pentru char c = 'a'; c += 2;, c devine 'c'.

Atribuirea în interiorul unei condiții

Idiomul while ((c = getchar()) != EOF) citește un caracter, îl memorează și apoi îl compară. Parantezele interioare sunt obligatorii: != are prioritate mai mare decât =, iar fără ele c ar primi rezultatul comparației (0 sau 1).

Evaluarea unică a operandului stâng

În v[f()] += 1 funcția f se apelează o singură dată; în v[f()] = v[f()] + 1 se apelează de două ori, posibil cu rezultate diferite. Atribuirea compusă nu este doar o prescurtare de scriere.

9. Alți operatori — privire de ansamblu

Incrementare și decrementare: ++, --

Operatorul condițional ?:

conditie ? expr1 : expr2 — dacă condiția este adevărată, valoarea este expr1, altfel expr2; se evaluează doar una dintre ele.

Operatorul virgulă

e1, e2 evaluează e1, îi ignoră valoarea, apoi evaluează e2; valoarea întregii expresii este cea a lui e2. Are cea mai mică prioritate dintre toți operatorii. Se folosește mai ales în for: for (i = 0, j = n - 1; i < j; i++, j--). Virgulele din lista de argumente f(a, b) sau dintr-o declarație int a, b; sunt simpli separatori, nu acest operator.

Operatorul sizeof

Dă dimensiunea în octeți a unui tip sau a unei expresii: sizeof(char) este întotdeauna 1, sizeof(int) este de obicei 4, sizeof(double) 8. Rezultatul are tipul size_t (fără semn). Pentru expresii parantezele nu sunt obligatorii: sizeof x.

Adresă și indirectare: &, *

&x este adresa variabilei x în memorie, iar *p este valoarea aflată la adresa p. Acești operatori unari stau la baza lucrului cu pointeri.

  • sizeof nu evaluează operandul: după int i = 1; sizeof(i++); variabila i rămâne 1 — compilatorul are nevoie doar de tipul expresiei.
  • Tipul rezultatului lui ?: este tipul comun al celor două ramuri: cout << (true ? 'A' : 66); afișează 65, nu A, pentru că tipul comun al lui char și int este int.

10. Efecte secundare și comportament nedefinit

Un efect secundar este o modificare a stării programului produsă de evaluarea unei expresii: o atribuire, ++/--, o afișare, apelul unei funcții care modifică ceva. Standardul garantează ordinea efectelor secundare doar în anumite puncte („puncte de secvență” în C, relația sequenced-before în C++):

  • la sfârșitul fiecărei expresii complete (la ;);
  • după operandul stâng al lui &&, ||, , și după condiția lui ?:;
  • înainte de intrarea în corpul unei funcții (toate argumentele sunt deja evaluate).
Regula de aurÎntre două astfel de puncte nu modifica aceeași variabilă de două ori și nu o citi în altă parte a expresiei în care o modifici. Altfel programul are comportament nedefinit (undefined behavior, UB): compilatorul poate produce orice rezultat, iar compilatoare diferite — sau același compilator cu alte opțiuni de optimizare — dau rezultate diferite.

Lista comportamentelor nedefinite întâlnite în această lecție

  • depășirea domeniului la tipurile întregi cu semn (INT_MAX + 1);
  • împărțirea sau restul întreg cu 0;
  • deplasarea cu un număr negativ de poziții sau cu cel puțin lățimea tipului; deplasarea la stânga a unui număr negativ (C, C++ înainte de C++20);
  • conversia unui real într-un întreg care nu îl poate reprezenta;
  • modificări nesecvențiate ale aceleiași variabile;
  • folosirea valorii unei variabile locale neinițializate.
Instrumenteg++ -Wall -Wextra semnalează multe dintre aceste situații la compilare (de exemplu „operation on 'i' may be undefined”), iar g++ -fsanitize=undefined le detectează în timpul execuției (depășiri, deplasări invalide, împărțiri la zero).

Partea a II-a — Seminar

S1. Evaluare manuală, pas cu pas

Pentru fiecare expresie: (1) stabilește ordinea în care se aplică operatorii; (2) calculează pe hârtie valoarea, cu toate rezultatele intermediare; (3) scrie răspunsul și verifică-l. Abia apoi deschide rezolvarea pas cu pas. Toate variabilele și constantele sunt de tip int, dacă nu se precizează altfel; răspunsul cerut este ceea ce ar afișa cout << (expresie).

S2. Grilă — exerciții tipice

Alege răspunsul; explicația apare imediat. Scorul se calculează doar pentru întrebările vizibile pe traseul ales.

S3. Scrie tu expresia

Scrie în sintaxă C/C++ o expresie care este adevărată (nenulă) exact în situația descrisă. Expresia ta este verificată automat pe toate valorile din domeniul indicat; dacă există o diferență, primești un contraexemplu.

S4. Verificatorul de echivalență

Sunt cele două condiții echivalente? Introdu două expresii cu variabile întregi (cel mult trei variabile); verificatorul le evaluează pentru toate combinațiile de valori din domeniu și compară valorile de adevăr.

Partea a III-a — Laborator

L0. Pregătire

Programele se compilează cu orice compilator C++ modern (g++, clang++, Visual Studio) sau cu un compilator online. Recomandat, din linia de comandă:

-Wall -Wextra activează avertismentele care prind multe dintre greșelile din această lecție (= în loc de ==, x & 1 == 0, comparații signed/unsigned). Citește avertismentele — nu sunt opționale.

Pentru a detecta comportamentul nedefinit în timpul execuției:

L1. Evaluatorul interactiv de expresii

Scrie declarațiile variabilelor și o expresie C/C++. Evaluatorul construiește arborele expresiei, arată forma complet parantezată (gruparea stabilită de priorități și asociativitate), aplică operatorii unul câte unul și explică fiecare pas: conversii, împărțiri întregi, scurtcircuitări, efecte secundare, avertismente.

sau apasă Enter în câmpul expresiei
Ce știe evaluatorul (și ce nu)
  • Operatori: aritmetici, relaționali, de egalitate, logici (cu scurtcircuitare), pe biți, atribuiri simple și compuse, ++/-- prefixat și postfixat, ?:, virgulă, sizeof, conversii (tip) și static_cast<tip>( ).
  • Constante: întregi zecimale, hexazecimale (0x1F) și octale (017), reale (2.5, 1e3, 2.5f), caractere ('a', '\n'), true/false.
  • Semantica este cea din C++ pe o platformă tipică: int pe 32 de biți, complement față de 2, comparațiile au tipul bool. În C, aceleași comparații au tipul int, cu aceleași valori 0/1.
  • Când ordinea de evaluare nu este fixată de standard, evaluatorul lucrează de la stânga la dreapta; dacă rezultatul ar putea depinde de această alegere, afișează un avertisment.
  • Nu sunt suportate: tipurile unsigned și long, tablourile, pointerii, apelurile de funcții, șirurile de caractere.

L2. Programe de rulat, modificat și extins

Pentru fiecare program: rulează-l, compară ieșirea cu cea așteptată, apoi rezolvă cerințele. Indiciile și soluțiile sunt ascunse — încearcă întâi singur.

L2.1 · Operațiile cu întregi

Ieșire pentru a = 17, b = 5:

a + b = 22 a - b = 12 a * b = 85 a / b = 3 (impartire intreaga) a % b = 2 (restul) a / b real = 3.4 verificare: (a/b)*b + a%b = 17

Cerințe:

  1. Rulează pentru a = -17, b = 5 și pentru a = 17, b = -5. Notează semnul câtului și al restului. Ce regulă observi?
  2. Rulează pentru b = 0. Ce se întâmplă? Adaugă o verificare if (b == 0) care afișează un mesaj și oprește programul.
  3. Ce se schimbă dacă scrii (double)(a / b) în loc de (double)a / b? Explică.
Răspunsuri

1) −17 / 5 = −3, −17 % 5 = −2; 17 / −5 = −3, 17 % −5 = 2. Câtul se trunchiază spre zero, restul are semnul deîmpărțitului, iar identitatea (a/b)·b + a%b = a rămâne adevărată. 2) Programul se oprește brusc (împărțire întreagă la zero — comportament nedefinit). 3) (double)(a / b) convertește un cât deja trunchiat: pentru 17 și 5 afișează 3, nu 3.4.

L2.2 · Cifrele unui număr de trei cifre

cifre: 7 4 2 suma cifrelor: 13 rasturnat: 247 palindrom: 0

Cerințe:

  1. Elimină parantezele din (s == u). De ce nu se mai compilează?
  2. Adaugă afișarea produsului cifrelor și a celei mai mari cifre (folosește ?:).
  3. Adaptează programul pentru un număr de patru cifre.
Indicii

1) << are prioritate mai mare decât ==: se încearcă (cout << "..." << s) == u. 2) int m = s > z ? s : z; m = m > u ? m : u; 3) Cifrele: n / 1000, n / 100 % 10, n / 10 % 10, n % 10.

L2.3 · Capcana împărțirii întregi

57 77 77 7 7.5

Cerințe:

  1. Explică de ce f3 este corect, deși conține tot constantele întregi 9 și 5.
  2. Scrie conversia inversă (Fahrenheit → Celsius, C = 5/9 · (F − 32)) în trei variante, dintre care una greșită. Verifică cu F = 212.
  3. Calculează media aritmetică a trei note întregi, afișată cu zecimale.
Răspunsuri

1) Asociativitatea stânga → dreapta: întâi c * 9 (double · int → double 225.0), apoi 225.0 / 5 este împărțire reală. 2) Greșit: 5 / 9 * (f - 32) dă 0; corect: 5.0 / 9 * (f - 32) sau (f - 32) * 5 / 9 → 100. 3) (n1 + n2 + n3) / 3.0.

L2.4 · Condiții compuse

Ieșire pentru 1900, 7, 15:

an bisect: false cifra: true litera: false x in [10, 20]: true x in afara [10, 20]: false

Cerințe:

  1. Testează anii 1900, 2000, 2024, 2025 și verifică rezultatele.
  2. Înlocuiește x >= 10 && x <= 20 cu 10 <= x <= 20. Compilează cu -Wall: ce avertisment primești? Pentru ce valori ale lui x rezultatul este greșit?
  3. Adaugă: „c este literă mică sau cifră”, „x este multiplu de 3 sau de 5, dar nu de amândouă”.
Răspunsuri

2) g++ avertizează că expresia X <= Y <= Z nu are sensul matematic. 10 <= x dă 0 sau 1, iar ambele sunt ≤ 20, deci rezultatul este mereu true — greșit pentru orice x în afara intervalului. 3) (c >= 'a' && c <= 'z') || (c >= '0' && c <= '9'); (x % 3 == 0) != (x % 5 == 0).

L2.5 · Scurtcircuitarea, observată direct

A() && B(): A -> 0 A() || B(): A B -> 1 B() || A(): B -> 1 A() & B(): A B -> 0 impartirea la zero a fost evitata

Cerințe:

  1. Explică fiecare linie. De ce la A() & B() se apelează ambele funcții?
  2. La linia a patra, ordinea afișării „A B” este garantată? Dar la primele trei?
  3. Inversează operanzii condiției din if. Ce se întâmplă la execuție?
Răspunsuri

1) & este operator pe biți: nu face scurtcircuitare, deci ambii operanzi se evaluează. 2) Nu: pentru & ordinea evaluării operanzilor nu este specificată, deci „B A” este la fel de corect. La && și || ordinea stânga → dreapta este garantată. 3) 10 / x se calculează cu x = 0 → împărțire la zero, programul se oprește.

L2.6 · Indicatori pe biți

00000011 00000001 00000101 poate citi? 1 n = 00101000, n & (n-1) = 00100000 putere a lui 2? 0 bitul 3 al lui n: 1

Cerințe:

  1. Scrie o expresie care este adevărată dacă sunt acordate toate drepturile din masca CITIRE | EXECUTIE.
  2. Afișează numărul de biți 1 din n folosind bitset<32>(n).count(), apoi verifică pe hârtie.
  3. Scrie expresia care păstrează doar ultimii 4 biți ai lui n și pe cea care îi pune pe toți patru pe 1.
Răspunsuri

1) (drepturi & (CITIRE | EXECUTIE)) == (CITIRE | EXECUTIE). 2) Pentru 40 = 00101000 sunt 2 biți de 1. 3) n & 0xF, respectiv n | 0xF.

L2.7 · Galeria capcanelor

Ieșire tipică (prima valoare poate varia, fiind rezultatul unui comportament nedefinit):

-1794967296 2500000000 4294967295 0 0 1 0 1

Cerințe:

  1. Compilează cu -Wall -Wextra. Ce linii primesc avertismente și de ce?
  2. Compilează și cu -fsanitize=undefined. Ce mesaj apare la execuție?
  3. Corectează fiecare linie problematică.
Răspunsuri

1) Comparația -1 < 0u (signed/unsigned) și x & 1 == 0 („suggest parentheses around comparison in operand of '&'”). 2) Un mesaj de tipul „signed integer overflow: 50000 * 50000 cannot be represented in type 'int'”. 3) (long long)a * b; nu amesteca signed cu unsigned; compară realii cu toleranță; pune paranteze: (x & 1) == 0.

L2.8 · Mini-proiect: analizorul de numere

Scrie un program care citește un întreg n și afișează, fără instrucțiuni repetitive, folosind doar operatori:

  1. dacă n este par, folosind & (verifică și pentru numere negative);
  2. reprezentarea binară pe 32 de biți și numărul de biți 1;
  3. dacă n este putere a lui 2;
  4. valorile n · 8 și n / 4 calculate prin deplasări (pentru n ≥ 0) și comparate cu rezultatele obținute cu * și /;
  5. valoarea absolută a lui n, cu operatorul condițional;
  6. dacă n este în intervalul [−100, 100] și are ultima cifră 0 sau 5.

Rezumat și fișă recapitulativă

Expresii

  • Expresie = operanzi + operatori; evaluarea dă o valoare de un anumit tip, eventual cu efecte secundare.
  • Operatori unari, binari și unul singur ternar (?:).
  • Gruparea: paranteze → prioritate → asociativitate.

Aritmetici

  • int / int → împărțire întreagă (trunchiere spre 0).
  • % doar pentru întregi; restul are semnul deîmpărțitului.
  • Depășirea pentru tipurile cu semn și împărțirea întreagă la 0: comportament nedefinit.

Conversii

  • bool/char/short → int (promovare).
  • „Mai mic” → „mai mare”: int → long → long long → float → double.
  • signed + unsigned → de regulă unsigned (capcană!).
  • La atribuire: conversie la tipul din stânga; real → întreg trunchiază.
  • Cast: (double)a / b, nu (double)(a / b).

Relaționali și logici

  • Rezultat 0/1 (bool în C++, int în C).
  • = atribuie, == compară.
  • a < b < c ≠ matematică → a < b && b < c.
  • &&, ||: scurtcircuitare, ordine stânga → dreapta.
  • De Morgan: !(p && q) ≡ !p || !q.
  • Realii nu se compară cu ==.

Pe biți

  • ~ & | ^ << >>, doar pentru întregi.
  • a << n = a·2ⁿ; a >> n = a/2ⁿ (a ≥ 0).
  • Măști: test (n >> k) & 1, set |=, clear &= ~, toggle ^=.
  • & ^ | au prioritate sub == → paranteze!

Atribuire și alții

  • Atribuirea are valoare; se înlănțuie de la dreapta la stânga.
  • v op= e ≡ v = v op (e).
  • ++x crește apoi folosește; x++ folosește apoi crește.
  • Virgula are cea mai mică prioritate; sizeof nu evaluează operandul.
  • O singură modificare a unei variabile pe expresie.
